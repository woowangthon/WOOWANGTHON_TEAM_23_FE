# WOOWANGTHON_TEAM_23_FE

프론트엔드 구현 레포. 스크롤 메이트 안드로이드 앱이 들어 있음.

## 개요

**스크롤 메이트**는 사용자가 올린 학습 자료(PDF, PPTX)로 서버가 만든 OX·단답 문제를, 유튜브 쇼츠를 넘기는 중에 카드로 띄워 주는 안드로이드 앱임. 숏폼을 막는 대신 이미 쓰는 숏폼 시간을 반복 학습의 기회로 바꾸는 것이 목적임.

- 자료 올리기: 파일 앱의 공유하기나 앱 안의 올리기 버튼으로 PDF·PPTX를 보내고 학습 주제를 고름. 서버가 문제를 만들면 앱이 내려받아 기기에 저장함
- 쇼츠 위 문제 카드: 쇼츠를 넘길 때 확률로 카드가 뜸. 답하면 카드 안에서 바로 결과(내 답과 정답)를 보여 줌. 건너뛰기도 가능함
- 시험일과 재출제: 학습 주제에 시험일을 넣으면 가까운 주제가 더 자주 나오고, 틀린 문제는 1일, 3일, 7일 간격으로 다시 나옴
- 홈: 오늘의 한마디와 오늘 쇼츠 시청 수치(본 시간, 넘긴 횟수, 맞힌 카드), 학습 주제와 D-day, 올린 자료 바로가기

문제를 언제, 무엇을 낼지와 채점은 기기의 규칙이 정하고, AI는 서버에서 문제와 오늘의 한마디 문장을 만드는 일만 함. 전체 구조와 API는 [DOCS 레포](https://github.com/woowangthon/WOOWANGTHON_TEAM_23_DOCS)의 `architecture.md`, `api.md`를 따름.

## 구조

```
[ 안드로이드 앱 ]                                      [ 서버 (BE + AI, Fly.io) ]
 ui/            홈, 자료 올리기 시트, 자료 목록, 접근성 안내 (Jetpack Compose)
 ScrollInterruptService   접근성 서비스: 쇼츠 진입·넘김 감지 → 카드 표시 (CardOverlay)
 domain/        규칙: 카드 등장 확률, 시험일 가중치, 재출제 간격, 채점 (Android 의존 없음)
 data/          Room: 학습 주제, 시험일, 자료, 문제, 풀이 기록, 시청 기록
 upload/ sync/  WorkManager: 백그라운드 업로드, 문제 내려받기, 풀이 기록 전송
 net/           OkHttp + kotlinx.serialization ── HTTPS ──>  https://scrollmate-be.fly.dev
```

- 앱은 BE만 부름. AI 서비스와 OpenAI API는 서버 안에 있고 앱에는 키가 없음
- 문제는 서버가 미리 만들어 기기에 저장하므로 카드는 네트워크 없이도 뜸
- 학습 주제와 시험일은 기기에만 저장하고 서버로 보내지 않음. 서버로 가는 것은 올린 파일, 풀이 기록, 시청 기록의 하루 합계임
- `domain/`의 규칙은 Android API를 쓰지 않는 순수 함수라 단위 테스트로 확인함

### 쇼츠 위에 카드가 뜨는 흐름

1. 접근성 서비스가 유튜브(`com.google.android.youtube`)의 화면 이벤트만 받아 쇼츠 화면(`reel_recycler`)에 들어왔는지, 넘겼는지 판단함
2. 넘길 때마다 `cardChance`로 확률을 정함: 쇼츠를 10분 볼 때까지 10%, 이후 10분 동안 20%까지 올라감. 쇼츠를 나가면 시간을 다시 셈
3. 광고 쇼츠(광고에만 있는 `reel_player_delegated_overlay`)가 보이면 카드를 띄우지 않고 다음 일반 쇼츠로 미룸
4. `CardQuestionSource`가 시험일 가중치(시험 14일 전부터 1에서 5까지)로 학습 주제를 고르고, 그 안에서 다시 낼 때가 된 문제, 아직 안 푼 문제 순으로 문제를 고름
5. 오버레이(`TYPE_ACCESSIBILITY_OVERLAY`)로 카드를 띄우고 오디오 포커스를 가져가 영상 소리를 멈춤
6. 답하면 기기에서 채점함(OX는 O/X 일치, 단답은 정답·허용 답안과 공백·대소문자 무시 글자 비교). 결과와 내 답을 카드 안에서 보여 주고 확인 버튼이나 4초 뒤에 닫음. 풀이 기록은 Room에 저장함

위 확률, 간격, 가중치 값은 임의로 정한 값이며 효과를 검증하지 않았음. 코드의 `CardPolicy.kt`, `ReviewSchedule.kt`에서 한곳에 모아 두고 조정할 수 있게 함.

## 기술 선택

| 선택 | 이유 | 대안과 한계 |
|---|---|---|
| 접근성 서비스 + 오버레이 | 다른 앱(유튜브 쇼츠) 위에 카드를 띄우고 쇼츠 진입·넘김을 알 수 있는 안드로이드의 정식 방법임 | 사용자가 설정에서 직접 켜야 함. 앱의 첫 화면에 안내함. 감지는 유튜브 앱의 화면 ID에 의존하므로 앱 업데이트로 어긋날 수 있음 |
| 규칙은 기기에서 계산 | 카드 등장, 출제, 채점, 재출제를 서버 없이 처리해 오프라인에서도 뜨고 응답이 즉시 나옴. AI가 판단할 일이 아님 | 서버가 사용자별 학습 상태를 모르므로 기기를 바꾸면 이어지지 않음 |
| 문제는 서버에서 미리 만들어 기기에 저장 | 카드를 띄울 때 AI 호출을 기다리지 않음 | 새 문제는 다음 동기화(15분 주기, 앱을 열 때)에 들어옴 |
| Room (기기 DB) | 학습 주제, 시험일, 문제, 풀이 기록을 구조화해 저장하고 조건으로 조회함 | 스키마를 바꿀 때 기존 데이터가 지워질 수 있는 설정이 남아 있음(`fallbackToDestructiveMigration`). 버전 1에서 2로는 마이그레이션이 있음 |
| WorkManager | 앱이 꺼져 있어도 업로드와 동기화를 재시도함 | 실행 시점이 시스템에 달려 정확히 15분마다는 아님 |
| Jetpack Compose + Material3 | 화면을 코드로 선언하고 상태 변화에 맞춰 갱신함. 쇼츠 위 카드는 오버레이라 XML 레이아웃을 씀 | |
| OkHttp + kotlinx.serialization | HTTP 호출과 JSON 변환. MockWebServer로 서버 없이 시험함 | |
| 로그인 없음 | 이번 제출에 넣지 않기로 함(2026-11-11). 기기 ID(`X-Device-Id`)로만 구분함 | 앱을 지우고 다시 설치하면 이전 자료를 받지 못함 |

구성 요소: Kotlin 2.2, Android Gradle Plugin 9.5, Compose BOM 2026.09, Room 2.8, WorkManager 2.10, OkHttp 5.5. minSdk 26, targetSdk 37.

## 실행 방법

안드로이드 앱은 `android/` 폴더를 Android Studio로 열어 실행함. 빌드와 단위 테스트는 `android/`에서 `./gradlew testDebugUnitTest assembleDebug`로 함.

### 개발 서버에 연결

- 디버그 빌드의 서버 주소는 `android/gradle.properties`의 `apiBaseUrl`로 정함. 기본값 `http://10.0.2.2:8080`은 에뮬레이터에서 PC(호스트)의 8080 포트에 닿는 주소임
- 서버(BE) 실행 방법은 BE 레포의 README 참고
- 실기기에서 PC의 서버에 붙으려면 `apiBaseUrl`을 PC의 같은 망 IP로 바꿈

### Android 17(API 37)에서 로컬 네트워크 권한

Android 17은 앱이 사설 주소(`10.0.2.2`, 같은 망 IP)에 접속할 때 `ACCESS_LOCAL_NETWORK` 권한을 요구함. 디버그 빌드의 매니페스트에는 선언해 두었지만, 설치 뒤에 권한을 허용해야 연결됨. 허용하지 않으면 연결이 10초 뒤 시간 초과로 실패하고 서버에는 요청이 찍히지 않음.

```
adb shell pm grant com.woowang.scrollmate android.permission.ACCESS_LOCAL_NETWORK
```

- 앱을 다시 설치하면 권한이 초기화되므로 다시 허용해야 함
- 릴리스 빌드는 배포 서버의 공개 주소(https)를 쓰므로 이 권한이 필요 없고 선언하지 않음

### 제출용 APK (릴리스 빌드)

`android/`에서 `./gradlew assembleRelease`로 만들고, 결과는 `android/app/build/outputs/apk/release/app-release.apk`에 있음.

- 릴리스 빌드는 배포 서버 `https://scrollmate-be.fly.dev`에 붙음. 주소는 `android/gradle.properties`의 `releaseApiBaseUrl`로 정함
- 바로 설치할 수 있게 디버그 키로 서명함. 스토어 배포용 서명이 아니며, 만든 PC마다 키가 달라 다른 PC에서 만든 APK로는 덮어 설치할 수 없음(앱을 지우고 다시 설치해야 함)
- 릴리스 빌드에는 개발용 샘플 문제가 없음. 서버에서 받은 문제가 없으면 카드가 뜨지 않음
- 올린 자료의 글자는 서버를 거쳐 OpenAI API로 전송됨
- 서버는 로그인이 없고 기기 ID로만 기기를 구분함. 앱을 지우고 다시 설치하면 기기 ID가 새로 생겨 이전에 올린 자료와 문제를 받지 못함

## 확인 방법

**단위 테스트**: `android/`에서 `./gradlew testDebugUnitTest`. 카드 등장 확률, 시험일 가중치, 재출제 간격, 채점, 서버 호출(MockWebServer), 동기화, 업로드 재시도를 시험함. 화면(Compose)과 접근성 서비스, Room의 실제 SQL은 단위 테스트로 시험하지 않음.

**폰에서 직접 확인** (제출용 APK: [Releases](https://github.com/woowangthon/WOOWANGTHON_TEAM_23_FE/releases))

1. APK를 설치하고 앱을 엽니다. Play 프로텍트 경고가 뜨면 '자세히 → 무시하고 설치'를 누릅니다
2. 첫 화면 안내에 따라 접근성 서비스를 켭니다
3. 파일 앱에서 PDF나 PPTX를 공유하기로 스크롤 메이트에 보내고 학습 주제를 골라 올립니다. 올리기 시트에 저작권과 OpenAI 전송 안내가 보입니다
4. 홈의 올린 자료 목록에서 문제를 만드는 진행이 보이고, 준비가 끝나면 문제가 생깁니다
5. 유튜브 쇼츠를 넘기면 확률로 카드가 뜹니다. 확률이 10~20%라 몇 번 넘겨야 할 수 있습니다
6. OX나 단답에 답하면 카드 안에서 내 답과 정답이 보이고, 확인을 누르거나 4초 뒤에 영상으로 돌아갑니다
7. 홈에서 학습 주제에 시험일을 넣으면 D-day가 보입니다

서버가 꺼져 있거나 서버에서 받은 문제가 없으면 카드가 뜨지 않음. 서버 동작은 `https://scrollmate-be.fly.dev/api/v1/health`로 확인함.

## 확인하지 못한 것, 하지 않은 것

- 쇼츠 감지와 카드 표시는 에뮬레이터(Android 17)에서 확인함. 실기기에서 확인한 범위는 기록하지 않았고, 기기와 유튜브 앱 버전이 다르면 화면 ID가 달라 쇼츠 감지가 어긋날 수 있음
- 광고 쇼츠 판별은 에뮬레이터의 유튜브 21.32.4에서만 확인함
- 시청 시간은 화면 변화 사이 간격을 더해 재는 값이라 실제 시청 시간과 다를 수 있음
- 인스타그램 릴스, 구글 로그인, 오답노트 화면은 만들지 않음. 안드로이드의 유튜브 쇼츠만 대상임
- 접근성 서비스를 다시 설치한 뒤 이벤트를 못 받으면 설정에서 서비스를 껐다 켜야 함
